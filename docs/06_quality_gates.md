# 06 Quality Gates

## Назначение
Определяет блокирующие критерии итоговой приемки `Pass/Fail` для барбершоп-стенда.

## Gate Defects
1. `Critical/Open = 0` обязательно.
2. `Major/Open = 0` или есть `Accepted with rationale` + `Expiry` в `docs/04_decisions.md`.
3. Любой открытый `Critical` автоматически переводит итог в `Fail`.

## Gate UX
1. Обязательны два сценария: основной (запись) и альтернативный (услуги/мастера -> запись).
2. Для каждого сценария обязательны три прохода:
- happy-path;
- invalid-path;
- recovery-path.
3. Неполное покрытие сценариев делает gate = `FAIL`.

## Gate A11y
1. Клавиатурная проходимость основных интерактивных элементов.
2. Видимый `focus-state`.
3. Логичная структура заголовков.
4. Управление фокусом в мобильном меню.

## Gate Performance
1. Нет критических ошибок консоли в основных сценариях.
2. Нет тяжелых неиспользуемых ассетов.
3. Между `v04` и `RC` нет деградации субъективной первой отрисовки.

## Gate Content
1. Единый стиль microcopy на русском языке.
2. Нет заглушек `lorem/todo/tbd` в UI.
3. Ошибки формулируют понятное действие пользователю.

## Правило финальной приемки
`Pass` ставится только если все gates имеют `PASS`.
Иначе итог: `Fail` или `Fail (Conditional)`.
